# 세션 간 인수인계

여러 대의 컴퓨터에서 서로 다른 세션이 같은 파이프라인을 나눠 맡고 있어,
합의한 내용을 사람이 옮겨 적지 않아도 되도록 **문서를 저장소에 둔다**.

- 이 저장소(`order-system`, macOS)는 **주문 웹앱** — 주문서·관리자 화면·회원 한도.
- 문항을 실제로 만들고 보내는 **제작기**(`프로젝트9 - claude`, WSL)는 별도 저장소다.

새 합의 문서는 `docs/handoff/YYYY-MM-DD-제목.md` 로 만들고 아래 표 맨 위에 한 줄 추가한다.
**본문은 마크다운이 원본**이다 — 웹 페이지 링크가 함께 있으면 같은 내용을 보기 좋게 옮긴 것일 뿐이고,
그 링크는 비공개라 상대 쪽에서 열리지 않을 수 있다.

| 날짜 | 문서 | 방향 | 내용 |
|---|---|---|---|
| 2026-09-09 | [변형문제 인쇄 양식](handoff/2026-09-09-변형문제-인쇄양식.md) | 웹앱 → 제작기 | PDF·DOCX 다운로드 스펙, 코드로 고정한 인쇄 양식, 회원별 `variantPrintFormat` |
| 2026-09-07 | [납품 정산 연동 규약](handoff/2026-09-07-납품정산-연동규약.md) | 웹앱 → 제작기 | 웹앱이 읽는 `orders.delivery` 필드, `shortfallByType` 추가 요청, 한도 집계 버그 2건 |
| 2026-09-07 | 납품 정산 기록 스펙 *(제작기 쪽 원본)* | 제작기 → 웹앱 | `delivered_serials` 구조, `orders.delivery` 신규 필드, 소급 가능 범위 |

## 작업 가이드라인

| 문서 | 내용 |
|---|---|
| [변형문제 작성](variant/AUTHORING.md) | 유형별 형식·CorrectAnswer·option_type·고난도 13종·무료 7종·저장 |
| [변형문제 검수](variant/REVIEW.md) | 사전검증 → 자동검수 → `cc:audit` 세 층, 층별로 못 잡는 것, 보정법 |

권위는 코드다(`lib/admin-variant-draft-claude.ts` 등). 위 문서는 코드가 강제하지 못하는
**실전 교정 규칙** — 실제로 틀렸던 것들 — 을 모은 것이라, 어긋나면 코드가 맞다.

## 상대 세션에 알리는 법

이 저장소를 체크아웃해 둔 컴퓨터에서 그 세션에 이렇게 말하면 된다.

```
next-order 저장소 pull 하고 docs/HANDOFF.md 읽어줘.
```

## 지금 걸려 있는 합의

**`orders.delivery`** — 제작기가 발송 직후 기록하고, 웹앱은 무료 한도 계산에서 읽는다.
웹앱이 실제로 쓰는 것은 두 필드뿐이다 ([`app/api/my/variant-base-quota/route.ts`](../app/api/my/variant-base-quota/route.ts)).

| 필드 | 우선 | 웹앱 동작 |
|---|---|---|
| `delivery.shortfallByType` | 1 | 유료 기본난도 유형의 부족분만 한도에서 뺀다 (정확) |
| `delivery.shortfall` | 2 | 총량을 그대로 뺀다 (무료 유형 부족까지 돌려주지만 고객에게 불리하지 않음) |

한도는 **유료 기본난도만** 센다. 무료 7종(주제·제목·주장·일치·불일치·순서·삽입)과
고난도는 처음부터 한도를 쓰지 않으므로, 총 부족분만 빼면 과잉 환급이 된다.

**아직 없는 것** — 부족분 포인트 환불, 관리자 목록의 납품·부족 열.
`delivery` 가 채워지기 시작하면 붙인다.
