# 로컬 LoRA — 맥(MLX)으로 이전

2026-09-23 · Windows GPU PC(GTX 1050 Ti 4GB) → 맥북 프로 Max

관리자 화면 「로컬 LoRA로 초안」은 Windows GPU PC 에서 끝까지 동작하는 것까지 확인했다.
하지만 4GB GPU 로 쓸 수 있는 모델(0.5B)은 정답을 자주 틀려, **학습·추론은 맥북 프로 Max 로 옮긴다.**
Windows 는 테스트까지만 하고, 맥 워커가 뜨기 전까지 배포 화면 버튼을 받는 용도로 켜 둔다.

## 1. 지금 동작하는 것

- 배포 사이트 관리자 「로컬 LoRA로 초안」 → MongoDB `local_variant_jobs` → GPU PC 워커(`ml/worker`) → 편집창 채움.
  API 키 없음. 필드·상태 규약: [로컬 LoRA 작업 큐](2026-09-23-로컬-LoRA-작업큐.md)
- 워커(Windows): 작업 스케줄러가 로그인 때 창 없이(pythonw) 띄운다. 로그 `ml/worker/logs/worker.log`.
  네트워크·DB 오류에도 끝나지 않고 재시도한다(#42). 사용법: [`docs/ml/local-variant-worker.md`](../ml/local-variant-worker.md)
- 학습된 어댑터는 **주제 하나**: Qwen2.5-0.5B-Instruct LoRA r8, 400단계(3시간 33분), eval loss 1.014.
  제목·주장은 학습하지 않았다(같은 0.5B 라 의미 없음).
- 한 문항: 처음엔 모델 올리기 1.5~3.5분 + 생성 약 3분이었는데, 원인이 모델이 아니라 **Windows 가 백그라운드 워커를 느리게
  돌린 것**이었다 — 작업 스케줄러 기본 우선순위(보통 이하)와 효율 모드(EcoQoS, 하이브리드 CPU 의 효율 코어). 둘을 고친 뒤
  모델 올리기 11초 + 생성 약 32초, 이 PC 는 학습을 안 하니 모델을 24시간 올려 둔다(2026-09-24).
- 라이브 확인 2건(26년 9월 고1): 21번은 정답이 맞음(표현만 어색), 33번은 틀림(아래 2절).

## 2. 알게 된 것 — 맥에서도 그대로 적용된다

- **형식은 맞추지만 정답이 자주 틀린다.** 원문 그대로·선지 5개·한국어 해설은 잘 나오는데, 그래서 오히려 틀린 문항이 그럴듯해 보인다.
  사람이 정답부터 보는 **초안 도우미**로만 쓴다(저장하면 `status=대기`, `ai_source=local-topic-lora`).
- **가장 흔한 실패는 「통념 → 반박」 지문이다.** 도입부의 통념을 주제로 잡는다.
  예: 26년 9월 고1 33번 — 글은 "미술을 모방으로 정의하는 것은 부족하다"인데, 모델은 반박당하는 "그리스인은 미술을 모방으로 봤다"를 정답으로 냈다.
  수능 지문에 이 구조가 많아 자주 드러난다.
- **작은 모델에게 검증·수정을 시키면 오히려 망친다.** 0.5B 검증기는 거의 모두 불합격을 냈고, 좋은 초안을 "1579" 같은 수정안으로 바꿨다.
  세 번 불합격이면 주제문을 정답 자리에 넣는데, 주제문이 세부 사실이면 그대로 틀린 정답이 된다.
  검증을 내용어 겹침 판단으로 바꿔 봤지만 시험 세트에서 더 나빠져 반영하지 않았다(5절).
- **LoRA 는 학습한 형식에서만 믿을 만하다** — `SYSTEM_PROMPT + 지문 → 문항 JSON`. 주제문 뽑기·해설 같은 다른 단계는 어댑터를 끄고 베이스로 돌린다(e6d2985).
- **베이스 0.5B 는 영어 칸에 한국어를 넣고, 한국어 주제문은 자주 깨진다**("아시아의 아티스트" 등). 영어 칸의 한국어는 버린다(#43).
  대체 해설이 깨진 한국어 주제문을 그대로 인용하는 문제는 남아 있다 — 해설은 사람이 고쳐 쓴다.
- 특정 예문에 맞춘 고정 대체 문구는 다른 지문에서 무관한 선지를 만든다 — 모르면 **실패로 끝내는 편**이 낫다(#43).

## 3. 맥에서 할 일

1. **학습** — 데이터는 같은 명령으로 뽑는다: `npm run cc:topic-export` → `data/topic-finetune/{train,valid,test}.jsonl`.
   MLX LoRA 스크립트 `ml/topic/train.sh` 가 이미 있다. 베이스는 **7B 급**(예: Qwen2.5-7B-Instruct 4bit)부터 — 메모리 여유가 크면 14B 도.
   MLX 어댑터와 Windows(HF/peft) 어댑터는 서로 호환되지 않는다([`topic-windows-cuda.md`](../ml/topic-windows-cuda.md) §6).
2. **워커 MLX 백엔드** — 큐·하트비트·lease·재시도는 백엔드와 무관하다(`ml/worker/local_variant_worker.py`).
   모델 실행만 `ml/worker/inference_child.py` → `ml/common/cuda_runtime.py`(torch·peft)에 묶여 있다.
   파이프라인(`ml/*/windows/pipeline_*.py`)은 `chat_text(..., use_adapter=)` · `set_adapter` · `adapter_off` 만 쓰므로,
   같은 인터페이스의 MLX 구현을 만들고 자식 프로세스가 백엔드를 고르게 하면 파이프라인을 그대로 쓴다.
   `gpu_memory()`(nvidia-smi 로 VRAM 여유 확인)는 맥(통합 메모리)에선 끄거나 다른 기준으로 바꾼다.
3. **자동 시작** — 작업 스케줄러 대신 launchd(LaunchAgent). 워커의 `--log-file` · 네트워크 재시도 · 잠금 파일은 그대로 쓴다.
   **백그라운드로 띄운 워커가 느려지지 않는지 꼭 잰다.** Windows 에선 작업 스케줄러 기본 우선순위와 효율 모드 때문에 같은 코드가
   5~9배 느렸다. launchd 도 `ProcessType` 을 지정하지 않으면 CPU·I/O 를 가볍게 제한한다고 되어 있으니 `Interactive` 로 두고,
   직접 돌린 시간과 워커를 거친 시간을 비교한다(`eval_pipeline.py` 한 지문 vs 관리자 화면 한 건).
4. **품질 시험** — `ml/topic/windows/eval_pipeline.py`(지금은 CUDA 런타임을 부르니 MLX 판으로 바꿔 쓴다).
   시험 세트는 `test.jsonl` 의 서로 다른 지문 5개 + `data/topic-finetune/eval_extra.jsonl`(로컬 전용 — 맥에서 다시 만든다):
   - 26년 9월 고1 영어모의고사 21번 — gold: `the importance of moving, which is what humans were designed to do`
   - 26년 9월 고1 영어모의고사 33번 — gold: `the limitation of defining art as simply copying reality`
   - 직접 쓴 지문(정보가 많을수록 정확도는 그대로, 확신만 커진다) — gold: `extra information raising confidence rather than improving the accuracy of decisions`
     (본문은 Windows 쪽 `eval_extra.jsonl` 셋째 줄. 한 줄 형식 `{"source","paragraph","gold"}`)
5. **전환** — 맥 워커가 관리자 화면에서 「GPU 워커 온라인」으로 보이면 Windows 워커를 멈춘다
   (`Stop-ScheduledTask -TaskName gomijoshua-local-variant-worker`, 자동 시작까지 끄려면 `Unregister-ScheduledTask …`).
   둘 다 켜 두면 먼저 집는 쪽이 처리하는데, 품질이 다르니 하나만 켠다.

## 4. 개선 루프 — 이렇게 하기로 했다

- 고치면 **같은 시험 세트로 전후를 비교**하고, 나을 때만 반영한다. 지문 하나를 한 번 돌린 결과로 판단하지 않는다.
- 라이브에서 틀린 지문은 `eval_extra.jsonl` 에 넣는다 — 다음 수정이 그 약점을 고쳤는지 바로 보인다.
- 관리자 화면에서 로컬 LoRA 초안을 **고쳐 저장한 문항**(`ai_source=local-topic-lora`)을 모아 재학습 데이터로 쓴다.
  모델이 틀리는 지점을 사람이 정확히 바로잡은 데이터다.

## 5. 0.5B 기준선 — 맥에서 넘어야 할 수치

시험 세트 8지문(test.jsonl 5 + eval_extra 3) × 2회, 채점은 사람(맞음/부분/틀림):

| 버전 | 맞음 | 부분 | 틀림 | 실패 | 평균 |
|---|---|---|---|---|---|
| **main — 지금 운영 중** | **6** | 0 | 10 | 0 | 37초 |
| 1회차 시도: 주제문에 전환어 문장 힌트 + 검증 대신 「초안 정답 ↔ 주제문 내용어 겹침」 판단 | 2 | 5 | 7 | 2 | 57초 |

- main 이 맞힌 지문: 양육 · 10대 · 21번(움직임). 틀린 지문: Pazano · 축구 · 쇼베 · 33번 · 직접 쓴 지문 —
  세부 사실(「since 1579」, 「유명한 유적」)이나 반박당하는 통념을 정답으로 냈다.
- 1회차는 축구(틀림→부분 2회)·직접 쓴 지문(부분 1회)은 나아졌지만 10대·21번이 맞음→틀림/실패로 나빠졌고,
  목표였던 33번·Pazano 는 그대로 틀렸다 → **반영하지 않았다.** 코드는 브랜치 `exp/topic-claim-turn-iter1` 에 남겼다.
- 결론: 0.5B 에선 프롬프트·판단 규칙을 바꿔도 틀리는 지문이 옮겨 다닐 뿐이다 — 병목은 모델의 독해력.
  맥에서 7B 급으로 올린 뒤 **같은 시험 세트로 main 수치(맞음 6/16)를 기준선 삼아** 비교한다.
  1회차 아이디어(전환어 힌트·겹침 판단)는 독해력이 받쳐 주는 큰 모델에서 다시 시험해 볼 만하다.
