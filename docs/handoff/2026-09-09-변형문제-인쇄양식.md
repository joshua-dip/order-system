# 변형문제 인쇄 양식 (PDF · DOCX)

**방향: 웹앱 → 제작기** · 2026-09-09

변형문제를 지면으로 뽑는 경로가 이 저장소에 **두 갈래**로 있다.
둘은 코드도 모양도 다르다. "정해진 양식" 이라고 부르는 것이 어느 쪽인지 먼저 맞추자.

| | A. 관리자 다운로드 | B. 코드로 고정한 인쇄 양식 |
|---|---|---|
| 실체 | `app/api/admin/generated-questions/download-pdf/route.ts` | `lib/variant-print-html.ts` |
| 출력 | PDF(pdfkit) · DOCX(docx) | HTML (브라우저 인쇄 전제) |
| 메뉴 | **변형문제 관리** `/admin/generated-questions` 상단 버튼 | **없음 — 호출자가 하나도 없다** |
| 단위 | 필터에 걸린 전부를 한 파일에 | **한 파일 = 한 유형** |
| 지금 쓰이나 | 예 | 아니오 (설정만 저장됨) |

## A. 관리자 「변형문제 관리」 다운로드 — 지금 실제로 나오는 것

`/admin/generated-questions` 필터 줄 오른쪽의 `PDF 다운로드` · `DOCX 다운로드`
([page.tsx:4215](../../app/admin/generated-questions/page.tsx)). 화면에 걸어 둔 필터를
그대로 쿼리로 넘겨 새 탭으로 라우트를 연다.

### 쿼리 파라미터

| 파라미터 | 뜻 |
|---|---|
| `textbook` · `type` · `difficulty` · `status` · `passage_id` · `free` | 화면 필터 그대로 (`free` = `only`\|`paid`) |
| `types` | 콤마 구분 다중 유형. `type` 이 있으면 무시된다 |
| `sources` | **주문 한 건만 뽑을 때.** `orderMeta.selectedLessons` 를 콤마로 이어 넘긴다 |
| `format` | `pdf`(기본) \| `docx` |
| `answer` | `0` 이면 정답·해설을 뺀다 → **학생용 문제지** |

정렬은 `textbook → source → type → question_data.순서`.
**건수 상한은 500문항**, `sources` 를 넘기면 2000. 교재만 걸고 뽑으면 500에서 잘려
주문하지 않은 회차가 섞이므로 **주문 단위는 반드시 `sources` 를 쓴다.**

파일명은 `변형문제_<교재명>.pdf` (교재 없으면 `전체`).

### 지면 스펙 (PDF)

A4 · margin 40 · 하단 한계 y=780. 머리말은 「변형문제 모음」 16pt 가운데 →
필터 설명 9pt 회색 → `총 N문항`.

문항마다:

```
#12  09회 18번  [순서]  난이도: 상        ← 7pt #999
발문                                        ← 10pt
  본문                                      ← 9pt / 들여쓰기 10 / lineGap 3
    ① …                                     ← 9pt / 들여쓰기 14
정답: (3)                                    ← 8.5pt #1a5276
  해설                                       ← 7.5pt #555
──────────────────────────────────────       ← #ddd 0.5pt 구분선
```

- `Paragraph` 에 `###` 가 있으면 **첫 청크를 주어진 문장으로 보고 9.5pt**, 나머지를 본문 9pt.
  `###` 없이 `\n\n` 만 있으면 첫 문단만 9.5pt.
- **원형숫자는 `①`→`(1)` 로 치환된다.** 폰트(NanumGothic)에 글리프가 없다.
  DOCX 는 맑은 고딕이라 치환하지 않는다 — **같은 문항이 PDF 와 DOCX 에서 다르게 보인다.**
- 선택지가 **번호뿐이면 통째로 생략**한다(어법·삽입). 지문 안의 ①~⑤ 를 고르는 형식이라
  빈 줄 다섯 개가 되는 것을 막는다.
- HTML 태그는 `stripHtml` 로 전부 제거된다 → **`<u>` 밑줄이 사라진다.**
  함의·어법·빈칸에서 밑줄이 의미를 갖는데 A 경로에서는 표시되지 않는다. (B 는 살린다.)

### 한글 폰트

`lib/fonts/NanumGothic-Regular.ttf` 를 읽고, 없으면 jsDelivr 에서 8초 타임아웃으로 받아
프로세스 메모리에 캐시한다. **Lambda 에 폰트 파일이 없으면 매 콜드스타트마다 외부 fetch** 이므로
배포본에 ttf 가 포함돼 있는지 확인할 것.

## B. `lib/variant-print-html.ts` — "정해진 양식" 의 원본

2026-08 에 선생님께 나간 자료(수능만만 09회)를 그대로 재현하려고 코드에 고정한 것이다.
그 자료는 화면을 Chrome 「PDF로 저장」으로 뽑은 일회성이었고 코드에 남아 있지 않았다.

**한 파일 = 한 유형** 이 원칙이다 — 「글의 순서.pdf」·「문장 삽입.pdf」. 수업에서 나눠 줄 때
유형이 섞이면 곤란하다. 유형 코드가 아니라 인쇄용 이름으로 찍는다.

| 코드 | 인쇄명 | 코드 | 인쇄명 |
|---|---|---|---|
| 순서 | 글의 순서 | 주제 | 글의 주제 |
| 삽입 | 문장 삽입 | 제목 | 글의 제목 |
| 빈칸 | 빈칸 추론 | 주장 | 필자의 주장 |
| 요약 | 요약문 완성 | 일치 / 불일치 | 내용 일치 / 내용 불일치 |
| 함의 | 밑줄 함의 | 무관한문장 | 무관한 문장 |
| 어법 / 어휘 | 어법 / 어휘 | | |

`-고난도` 접미사는 `(고난도)` 로 바뀐다 (`hardSuffix` 로 끌 수 있음).

### 지면 규칙

- 머리말: 굵은 제목 17pt + 부제 8.5pt, 아래 2px 실선. 오른쪽 `brand` 는 **기본 빈 값** —
  선생님이 학생에게 그대로 나눠 주는 자료라 공급처 이름을 빼기로 했다(2026-08-29 지시).
- 문항: 검은 번호 배지 + 출처 라벨 → 굵은 발문 → **테두리 친 본문 박스** → 선택지.
  `break-inside: avoid` — 지문이 페이지 중간에서 잘리면 풀 수가 없다.
- **정답·해설은 `break-before: page` 로 다음 장부터.** 문제만 먼저 나눠 주기 쉽게.
- `<u>…</u>` **만** 살린다. 전부 이스케이프한 뒤 `<u>`·`</u>` 만 되돌리는 방식이라,
  본문에 글자로 쓰인 `<AARP>` 같은 꺾쇠(113곳)는 그대로 보이고 임의 태그는 막힌다.
- `###` 만 있는 줄은 지운다(블록 구분자). 문단이 이미 나뉘므로 선은 긋지 않는다.
- 선택지가 번호뿐이면 세로로 늘어놓지 않고 **한 줄로 모은다**.

### 회원별 설정 — `users.variantPrintFormat`

회원 상세 `/admin/users/[id]` 「커스텀 양식」에서 저장한다. 주문마다 다시 고르지 않기 위한 것.

| 키 | 기본 | 뜻 |
|---|---|---|
| `brand` | `''` | 머리말 오른쪽 표기. 비면 안 찍음 |
| `includeAnswers` | `true` | 정답·해설 별지 첨부 |
| `splitByType` | `true` | 유형별로 파일 분리 |
| `hardSuffix` | `true` | 유형명 뒤 `(고난도)` |

> ⚠️ **저장만 되고 출력에는 반영되지 않는다.** `buildVariantPrintHtml` 을 호출하는
> 라우트·스크립트가 이 저장소에 **하나도 없다**(git 전체 이력 기준). 회원 상세는
> `normalizeVariantPrintFormat` 으로 값을 정규화해 저장할 뿐이고, 지금 관리자 화면에서
> 뽑히는 PDF 는 A 경로라 이 설정을 보지 않는다.

## 제작기 쪽에 확인이 필요한 것

1. **실제 납품 PDF 를 무엇으로 뽑고 있나.** 웹앱 A 경로인지, B 를 옮겨 쓰는지,
   아니면 제작기 자체 렌더러가 따로 있는지. 2026-08-30 커밋에 "첫 출력물" 언급이 있는데
   이 저장소에는 그걸 만든 호출자가 없다.
2. **B 를 라우트로 붙일지.** 붙인다면 `/api/admin/generated-questions/print`
   (회원 id 로 `variantPrintFormat` 을 읽어 유형별 HTML 반환) 정도가 자연스럽다.
   웹앱에서 하겠다면 이쪽에서 만들고, 제작기가 이미 하고 있으면 B 는 제작기로 넘긴다.
3. **밑줄 처리.** A 는 `<u>` 를 지우고 B 는 살린다. 납품물에 밑줄이 필요하면 A 로는 안 된다.

## 데이터 계약 (양쪽 공통)

`generated_questions.question_data` 에서 읽는 키 — 대소문자 두 벌을 모두 받는다.

| 키 | 비고 |
|---|---|
| `Question` / `question` | 발문 |
| `Paragraph` / `paragraph` | 본문. `###` 는 블록 구분자, `\n\n` 는 문단 |
| `Options` / `options` | `###` 구분 우선, 없으면 줄바꿈 구분(레거시) |
| `CorrectAnswer` / `correctAnswer` | `①`~`⑤` |
| `Explanation` / `explanation` | 문자열 `'undefined'` 는 걸러진다 |

문서 자체에서는 `source` · `type` · `difficulty` 를 머리줄에 쓴다.
