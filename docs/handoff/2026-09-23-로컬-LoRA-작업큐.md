# 로컬 LoRA 작업 큐 — 웹앱 ↔ GPU PC 워커

**방향: 웹앱 → GPU PC 워커** · 2026-09-23

관리자 화면의 「로컬 LoRA로 초안」(주제·제목·주장)은 웹 서버가 직접 만들지 않는다.
배포(Amplify)에는 GPU·모델이 없으므로 **웹앱은 MongoDB 에 작업을 넣고, GPU PC 의 워커가 꺼내 만든다.**
PC 는 Atlas 로 나가는 연결만 쓴다 — 포트·터널·새 환경변수가 없다. 이 문서는 두 쪽이 지키는 필드 규약이다.

- 웹앱: `lib/local-variant-jobs.ts`, `app/api/admin/generated-questions/local-jobs/**`, `…/local-worker`
- 워커: `ml/worker/local_variant_worker.py` (사용법 [`docs/ml/local-variant-worker.md`](../ml/local-variant-worker.md))

## `local_variant_jobs` — 작업 한 건

| 필드 | 쓰는 쪽 | 값 |
|---|---|---|
| `type` | 웹앱 | `주제` · `제목` · `주장` |
| `passage_id` · `textbook` · `source` | 웹앱 | 관리자 폼 그대로(ObjectId·문자열) |
| `paragraph` | 웹앱 | 등록 시 `getPassageTextForVariantCompare` 로 확정한 **영어 원문** — 워커는 `passages` 를 다시 읽지 않는다 |
| `status` | 둘 다 | 아래 상태표 |
| `requested_by` | 웹앱 | 관리자 loginId |
| `attempts` | 워커 | 집을 때마다 +1, GPU 가 바빠 되돌리면 −1. 3회면 더 집지 않는다 |
| `claimed_by` · `claimed_at` · `lease_until` | 워커 | 워커 id(호스트명) · 집은 시각 · 이 시각까지 처리 중(생성 중 15초마다 연장) |
| `result` | 워커 | `{ question_data, elapsed_ms, adapter: {main, explain, base_model}, pipeline }`, 시험 모드면 `fake: true` |
| `error` | 워커 | 실패 사유(한국어) |
| `created_at` · `updated_at` · `finished_at` | 둘 다 | Date. `finished_at` 이 있으면 30일 뒤 TTL 로 삭제 |

### 상태

| status | 누가 바꾸나 | 뜻 |
|---|---|---|
| `queued` | 웹앱(등록) · 워커(GPU 부족으로 되돌림) | 대기 |
| `running` | 워커 — `find_one_and_update` 로 원자적으로 집음 | 생성 중. `lease_until` 이 지나면 다른 워커가 다시 집을 수 있다 |
| `done` | 워커 | `result.question_data` 있음 |
| `failed` | 워커 | `error` 있음(미학습 유형·생성 실패·반복 중단) |
| `cancelled` | 웹앱(취소 버튼·모달 닫힘) | 워커의 완료 기록은 `status: running` 조건이라 취소된 작업의 결과는 버려진다 |

## `local_variant_workers` — 하트비트(워커 → 웹앱)

`_id` = 호스트명. 워커가 15초마다 덮어쓴다. 웹앱은 `last_seen` 이 45초 안이고 `state != stopped` 면 온라인으로 본다.

| 필드 | 값 |
|---|---|
| `state` | `idle` · `loading` · `running` · `gpu_busy`(여유 VRAM 부족 — 대개 학습 중) · `stopped` |
| `model_loaded` · `base_model` | 모델을 올려 둔 상태인지(작업이 없으면 10분 뒤 내려놓음) |
| `types` | `{ 주제: { trained, explain, base_model }, … }` — 화면이 미학습 유형 버튼을 끈다 |
| `fake` | `--fake` 시험 모드 |
| `gpu` | `{ name, free_mb, total_mb }` |
| `current_job` | 처리 중인 작업 id |

## 저장

워커는 `generated_questions` 에 쓰지 않는다. 결과는 관리자 화면 편집창에 들어가고, 관리자가 검토 후
평소처럼 저장한다. 이때 `ai_source` 가 `local-topic-lora` · `local-title-lora` · `local-claim-lora` 로 기록되고
(`POST`/`PATCH /api/admin/generated-questions` 는 이 세 값만 받는다), `status` 는 `대기` 로 채워진다.
정답 위치는 워커 파이프라인이 해설을 쓰기 직전에 ①~⑤ 로 섞는다.
