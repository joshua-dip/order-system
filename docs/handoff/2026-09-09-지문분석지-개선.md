## 코드 기준과 Mac에서 시작하는 방법
Windows main은 평가 당시 저장된 origin/main보다 126커밋 뒤였다. 아래 코드 검토는 작업 디렉터리의 오래된 파일이 아닌 `git show origin/main:<path>`를 기준으로 했다. 평가 당시에는 fetch하지 않았으며, Git 전달 준비 과정에서 fetch했다. 최신 기준은 아래 추가 메모를 참고한다.

- 검토한 origin/main: `fa688b8eac429f226654619a2bc2b1a7f1743931`
- Windows HEAD: `c9fbe86a1ada8087d5a824241de5ee5c57c9e54b`

Mac에서 먼저 `git status --short --branch`로 작업 상태를 확인하고, `git fetch origin` 후 현재 브랜치와 origin/main 차이를 확인한다. 다른 작업의 변경을 덮어쓰지 말고 최신 기준의 작업 브랜치에서 시작한다. 저장소의 AGENTS.md와 최신 docs/HANDOFF.md가 있으면 읽는다. 아래 파일이 없다면 오래된 체크아웃일 가능성이 높다.

## 데이터 호환성에서 주의할 점
- `compOf()`는 명명 필드와 `analysisResults.comprehensive['1'~'5']`를 모두 지원한다. 번호 필드 4를 무조건 ‘글의 흐름’으로 일괄 변경하기 전에 다른 시기의 저장 데이터에 실제 번역이 들어 있는지 조사한다. 이름만 바꿔 기존 데이터의 의미를 훼손하지 않는다.
- `vocabTables()`는 `v.synonym`을 항상 출력하고, 옵션이 켜져 있으면 `v.antonym` 앞에 `=`를, `v.opposite` 앞에 `↔`를 붙인다. 현재 표본의 반의어 오표기와 맞닿은 코드다. 필드 이름만 보고 바로 교체하기보다 생성 프롬프트·로더·저장 시대별 값의 뜻을 조사해 정상화한다. 동의어·반의어 OFF일 때 synonym도 남는 동작을 함께 검증한다.
- `renderSentence()`의 구문 범위 정렬과 닫기 처리를 확인한다. 공통 끝점의 중첩 구문에서는 안쪽 범위를 먼저 닫고 그 범위의 라벨을 붙여야 한다. 저장 데이터 자체가 교차하면 잘못된 중첩을 조용히 출력하지 않도록 검증한다.
- 문장 번호 오류는 해설 산문에 이미 ‘0~3’ 같은 문자열로 저장됐을 가능성도 있다. 렌더러에 일괄 +1을 넣는 것으로 해결된다고 가정하지 않는다.
- 로더는 SVOC 단어 인덱스·문자 오프셋·배열 형태를 정규화한다. 괄호 수정을 하다가 기존 SVOC 호환성을 깨뜨리지 않도록 한다.
- PDF는 `passages`와 `passage_analyses`의 `passageStates.main`을 다시 읽는다. 시점에 따라 데이터가 바뀔 수 있으므로 회귀 검증용 입력은 별도로 고정한다.

## 맥에서 참고 PDF를 찾는 방법
Dropbox 계정마다 루트가 `~/Library/CloudStorage/Dropbox` 또는 팀 Dropbox 이름으로 달라질 수 있다. Windows 절대 경로를 하드코딩하지 말고, 동기화된 **박준규 폴더**를 기준으로 아래 표본의 상대 경로를 찾는다. 원본 PDF를 Git 저장소에 대량 추가할 필요는 없다. PDF가 동기화되지 않았더라도 아래 관찰·재현 지문으로 구현을 시작할 수 있다.

기존 웹 출력 참고 파일: `10모의고사/영어/01_고1/2026학년도 9월 고1 영어모의고사/26년 9월 고1 영어모의고사 분석지 · 해설편.pdf`.
- 표지의 발행일 2026-09-03, 25지문, 총 60쪽.
- PDF 물리 4~5쪽: 18번 문장과 설명 분리, 반의어 표기.
- 6~7쪽: 19번 구문·번호·어휘.
- 34쪽: 31번 요약표·반의어.
- 2쪽: 실제 시작 쪽수가 없는 목차.
- 새 PDF 버튼은 실행했지만 새 파일 확보와 재렌더링은 완료하지 못했다. 따라서 인쇄 결함은 기존 파일에서의 관찰이며 최신 버전의 확정 결함으로 취급하지 않는다.

### 학습 설계 개선
1. **지문 전체 흐름을 먼저 보여주기.** 상단 또는 옆에 ‘핵심 주장 → 예시 → 전환 → 결론’을 짧게 표시하고 문장 번호를 연결한다. 19번은 ‘긴장(1~4) → 도움(5~7) → 안도(8~11)’처럼 장르에 맞춘다.
2. **기본 표시를 줄이고 수준별 양식을 제공하기.** 기초형은 해석·핵심 어휘·주절 S/V, 수업형은 핵심 어법 3~5개와 필기 여백, 심화형은 전체 구문·변형 근거를 사용한다. 현재 대부분의 해설 옵션이 켜져 있어 모든 정보가 비슷한 무게로 보인다.
3. **중요 문장 이름을 장르에 맞게 바꾸기.** 서사문의 도움 장면과 결말에 모두 ‘주제문’을 붙이기보다 ‘전환점’, ‘심경 변화의 근거’로 안내한다. 설명문·논설문에는 주장·근거·예시를 쓴다.
4. **‘변형 가능’과 ‘출제 우선순위’를 구분하기.** 18·19·31번은 8개 유형 중 6~7개가 표시되어 선별력이 낮다. 가능 유형 목록과 추천 2~3유형을 나누고, 문장 번호와 출제 근거를 적는다. 검증 근거 없이 확률로 표현하지 않는다.
5. **문제편의 목적을 선택하게 하기.** 현재 문제편에는 한글 해석과 어휘 뜻이 남는다. 이를 수업용으로 살리고, 자기 점검형에서는 뜻·해석을 숨기거나 해설편으로 넘긴다.
6. **설명을 적용하는 확인 문제 추가.** 밑줄 이유 설명 외에 핵심 어법 양자택일, 오류 수정, 연결어 빈칸, 지시어 대상 찾기, 근거 문장 찾기를 지문당 3~5개 제공한다. 정답에는 해당 문장과 이유를 연결한다.
7. **해설 교정.** ‘Our tastes are social.’을 ‘세 단어 주제문’이라고 부르는 오류, ‘정도를 눅여’ 등의 오타, ‘다진 샐러드 순간’ 같은 어색한 직역을 교정한다. 구문 분석 정확성과 한국어 설명 품질을 따로 검수한다.
8. **어휘의 문맥 의미·교체 가능성을 명확히 하기.** 표제어 뜻과 문장 속 뜻을 구분하고, 동의어라고 해도 원문 자리에 그대로 바꿀 수 있는지는 별도로 확인한다.

### 제작 화면 개선
- 미리보기 영역 확대, 전체 화면·확대/축소·페이지 맞춤 제공. 현재는 왼쪽 목록과 가운데 옵션이 넓고 오른쪽 미리보기가 좁다.
- 기본 미리보기를 표지 대신 첫 분석 본문으로 열고 표지/본문/어휘 바로가기 제공.
- 선택한 지문을 미리보기 대상으로 직접 지정. 현재 앞 2편 제한은 뒤쪽 긴 문장의 문제를 확인하기 어렵게 한다.
- 앞 2편 미리보기와 최종 전체 페이지 검사를 분리. 최종 출력 전 예상 쪽수와 넘침 경고 제공.
- ‘문제편+해설편’은 패널과 무관한 기본 양식임을 버튼 주변에 표시하거나, ‘기본 2종’과 ‘현재 설정’ 선택을 명확히 분리.
- 교재 검색은 aedebfd에서 추가됨: 최신 동작을 먼저 확인. 문항 번호 범위 선택, 선택 개수·최종 순서 표시 강화는 별도 개선 후보.
- 화면의 작은 회색 설명 글씨와 인쇄용 연한 색의 대비 개선. 색 외에 밑줄·기호·라벨로도 의미를 구분하는 흑백 양식 제공.
- 소량 배부는 표지·목차·판권을 생략하는 간편 출력, 책자는 포함하는 책자 출력으로 나누기.
