## 현재 상태

- 맥 MLX 12유형. 초안은 `Qwen2.5-7B-Instruct-4bit` + 유형별 LoRA, 판정·교정·해설은 `Qwen3.6-35B-A3B-4bit`. 순서·삽입·무관한문장·어휘·어법은 규칙 기반이다.
- main의 `03c6a0b` 요약 후보는 남아 있다. 이번 문장 번호 선택 방식만 **채택하지 않고 수정 전으로 복원**했다. 코드·어댑터 지문 일치, 기존 테스트 12개 통과. 이번 실험에서 재학습·운영 재개는 하지 않았다.
- 두 세트 요약 전체를 전후 각각 2회(총 144문항) 평가했다. O%: 고1 44.4→50.0, 고2 47.2→41.7로 모두 ±7%p 안의 같음. F%: 고1 27.8→27.8, 고2 27.8→19.4. 채점은 `grades/<세트>/2026-09-26-core-index-{before,after}.json`; **Codex AI 검토이며 독립 사람 채점은 아니다.**
- 상품 수준 미달. 의미·주어·인과·문법 오판과 복수정답이 남아 있다. 운영 워커·호환 서버는 중지 방침 유지; 이번 작업에서 켜지 않았다. 마지막 확인 시 워커 launchd 서비스는 미등록, 호환 서버도 미실행이었다. 실행 차단 코드는 없으므로 운영을 먼저 재개하면 요약 전 문항을 원문과 직접 대조해 검수한다.
- 상품 목표안은 노트 24과에 정리했다: 유형별 초안 O ≥90%·F ≤5%, 별도 새 지문 100문항 이상 검수, 최종본 알려진 치명 오류 0건 확인, 사람 작업시간 50% 이상 단축. 아직 달성한 기준이 아니며 P의 복수정답도 별도 치명 오류로 센다.

## 다음 할 일

1. 상품 검수표와 실제 오류 예시를 고정한다. 요약의 주어·인과·필자 입장 오류 중 **한 종류**를 다음 가설로 삼고, 두 개발 세트에서 같은 조건으로 전후 비교한다. 이번 사이클은 종료했다.
2. `jun11-go2`의 나머지 11유형을 평가해 우선 활용 후보를 고른다. 빈칸의 복수정답, 주제·제목의 무관 오답도 별도 점검한다.
3. 상품 판단용 새 지문 묶음을 개발 세트와 분리하고 학습 export에서 제외한다. 별도 검수자가 정답을 먼저 보지 않고 풀이하고, 실제 제작·검수시간을 측정한다.
4. 운영 재개가 결정된 뒤 `npm run cc:local-usage`로 수정·폐기 비율을 쌓는다. 기준을 통과한 유형부터 사람 검수 후 활용한다.
5. **Qwen3.8-27B 후보 시험은 보류 유지.** 실제 배포·MLX 호환성을 먼저 확인한 뒤 7B 초안 또는 35B 판정과 비교한다. 현재 품질 진단·상품 기준 정리가 우선이다.

## 작업 기준·참조

- **로컬 MLX만 사용, Anthropic API 호출 금지. `MONGODB_URI` 출력 금지. 커밋·푸시·배포는 사용자 요청 시만.** 어댑터·학습 데이터·평가 `runs/`는 git 제외, 채점 `grades/`는 기록 대상이다.
- 평가 교재는 `scripts/_eval-set-filter.ts`로 학습 export에서 제외한다. 새 세트는 `ml/eval/sets/`에 추가한다. 평가 실행은 잠자기 방지를 위해 `caffeinate -i`를 붙인다.
- 데이터 추출·학습·평가 명령과 채점 방법: [ml/eval/README.md](../../ml/eval/README.md). 성공 문항의 판정 근거도 보려면 `--keep-trace`.
- Cursor 호환 서버 설정·키·터널·재시작 주의: [cursor-openai-server.md](../ml/cursor-openai-server.md). 워커와 서버가 모델을 각각 올리므로 동시 실행 시 메모리에 유의한다.
- 핵심 코드: `ml/worker/local_variant_worker.py`, `ml/common/mlx_runtime.py`, `ml/summary/windows/pipeline_summary.py`, `ml/common/summary_draft.py`, `ml/common/summary_review.py`.
