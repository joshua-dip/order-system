# 분석지 작성 워크플로우 (Pro 전용 — 병렬 에이전트용)

한 회차의 지문들에 대해 **지문분석기 전 항목**을 작성해 `passage_analyses` 에 저장한다.
ANTHROPIC API 호출 금지. MongoDB 직접 접속 금지 — 아래 스크립트만 사용.

## 명령 순서 (지문마다)

```bash
# 1. 원문 받기 (회차 전체를 한 번에 — ★SKIP 표시 지문은 건너뛴다)
npx tsx scripts/cc-analysis-dump.ts "수능특강 Q 미니모의고사 영어 Start" "^03회 "

# 2. 초안 작성 → <스크래치>/s-<회차>-<번호>.json  (아래 스키마)
# 3. 인덱스 확정 (실패 시 오류 목록이 나옴 — 초안 고쳐 재실행)
npx tsx scripts/cc-analysis-resolve.ts <초안.json> <출력.json>
# 4. 검증
npm run cc:syntax -- save --json <출력.json> --dry-run   # "ok": true 확인
# 5. 저장 (한 번만)
npm run cc:syntax -- save --json <출력.json>
```

## 초안 스키마 (cc-analysis-resolve 입력)

```jsonc
{
 "passageId": "<덤프의 24자리 id>",
 "topic": [주제문 인덱스],            // 1~2개
 "essay": [서술형대비 인덱스],        // 2~3개 (어법·구문 밀도 높은 문장)
 "comprehensive": {                   // 전부 한글 산문. 번호 키 고정
  "1": "주제 — 이 글이 무엇에 관한 글인지 한 문장",
  "2": "요지 — 글의 중심 주장·정보를 한두 문장으로",
  "3": "요약 — 전개를 따라가며 3~4문장으로 압축",
  "4": "해석 — 글의 구조·신호어·전개 방식 해설 + 어울리는 출제 유형 언급",
  "5": "함의 — 함정이 되는 표현·다의어·출제 포인트를 짚기"
 },
 "chunks": { "0": ["끊어읽기", "조각들"], ... },   // ⚠ 모든 문장 인덱스 포함,
    // 조각을 공백으로 이어붙이면 원문과 정확히 일치해야 함(대시 ─, 따옴표, 세미콜론 포함).
    // 제목·인사말 같은 짧은 문장은 조각 1개로.
 "svoc": { "0": { "S": "주어 원문", "V": "동사 원문", "O": "목적어", "C": "보어" }, ... },
    // 각 역할 값은 원문 연속 토큰 그대로. 없는 역할은 키 생략.
    // 같은 표현이 여러 번이면 "Sn": 2 처럼 몇 번째 등장인지(기본 1).
    // ⚠ 명령문·인사말·조각문은 svoc 자체를 생략 (subject 필수 검증에 걸림).
    // ⚠ 축약형(we'd·They're·it's)은 한 토큰 — 쪼개 쓰지 말고 통째로 쓰거나 그 문장은 생략.
 "phrases": { "0": [ { "text": "원문 연속 구간", "label": "전치사구", "modifies": "꾸미는 대상", "depth": 0, "occ": 1 } ] },
    // label 예: 시간/이유/조건/양보 부사절 · 명사절 (목적어/보어) · 동격 명사절 · 주격/목적격/계속적 용법 관계절 ·
    //          관계부사절 · to부정사구 (목적/진주어/형용사적/목적격보어) · 전치사구 (동명사) · 분사구문 (이유/결과/동시 상황) ·
    //          과거분사구 · 현재분사구 · 동격 명사구 · 병렬 절. 중첩은 depth 1·2.
 "tags": [ { "s": 0, "text": "원문 연속 토큰", "tag": "어법명", "cat": "분류", "exp": "왜 이 형태인지 한두 문장" } ],
    // 지문당 6~12개. cat: 수일치·태·시제·분사·부정사·동명사·관계사·접속사·비교·병렬·조동사·가정법·대명사·동사 어법·어휘·전치사·어순
    // ⚠ text 는 반드시 그 문장의 "연속" 토큰 — 부사가 끼면(have often been used) 낀 채로 쓴다.
 "points": { "0": [ { "title": "짧은 제목", "content": "학생용 해설 한두 문장" } ] },   // 문장 절반 이상에
 "gwords": { "0": ["어법 표시 단어"] },   // tags 의 단어들 위주. "word#2" 로 등장 순서 지정 가능
 "cwords": { "0": ["문맥 핵심 어휘"] },   // 어휘 문제 후보. 구두점 붙은 채여도 됨
 "vocab": [ { "word": "기본형", "meaning": "뜻", "partOfSpeech": "n.", "cefr": "B2", "synonym": "…", "antonym": "…" } ]
    // 지문당 10~18개. 위치는 자동 탐색되므로 기본형으로. 숙어는 그대로("take for granted").
}
```

## 품질 기준 (실제 판매물)

- comprehensive 는 성의 있게 — 특히 4(구조 해설)·5(출제 포인트)가 이 자료의 값어치다.
  5번에는 다의어 함정·직역하면 무너지는 관용구·오답 선지가 노릴 지점을 짚는다.
- 주제문(topic)은 글의 요지가 실린 문장. 도표·안내문은 핵심 정보 문장.
- tags 의 exp 는 「왜 이 형태인가」를 학생에게 말하듯: "students 가 허용을 받는 쪽이라 수동."
- 실패 루프 금지: resolve 오류가 나면 해당 표현만 고친다(토큰 연속성·등장 순서 확인).
