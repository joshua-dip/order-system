# 분석지 내용 검수 워크플로우 (read-only 교차 검토)

작성자와 다른 눈으로, 저장된 분석의 **내용 오류만** 찾아 보고한다. **저장·수정 절대 금지** —
발견만 하고 고치는 것은 오케스트레이터 몫이다. ANTHROPIC API·Mongo 직접 접속 금지.

## 명령

```bash
# 1. 범위의 지문 id 목록 (★SKIP 이어도 머리줄에 id 가 나온다)
npx tsx scripts/cc-analysis-dump.ts "<교재명>" "<정규식>" | grep '═══'
# 2. 지문마다 저장 분석 전체 덤프 (sentences·koreanSentences 가 원문과 같다)
npm run cc:syntax -- export <passageId>
```

## 무엇을 잡나 (명백한 오류만 — 표현 취향·개선 제안은 보고하지 말 것)

1. **어법 태그**: tagName·category·explanation 이 selectedText 의 실제 문법과 다른 것
   (예: 능동인데 「수동태」, 접속사 that 인데 「관계대명사」, 수일치 설명의 주어 오인).
2. **문법 포인트·태그 해설의 사실 오류**: 설명 자체가 문법적으로 틀린 진술.
3. **종합분석 1~5**: 지문 내용과 어긋나는 진술(오독·사실 왜곡·인물/수치 뒤바뀜).
   슬롯 3(요약)의 사실 오류는 특히 치명적.
4. **어휘 뜻(vocab meaning)·유의어**: 문맥과 다른 오역 (다의어의 엉뚱한 뜻 등).
5. **svoc 역할 오지정**: 문법적으로 명백히 틀린 배정만 (목적어를 보어로 등.
   해석 여지가 있는 경계 사례는 보고하지 말 것).
6. **주제문(topic) 선택이 명백히 엉뚱한 경우** (지엽 문장·예시 문장을 주제문으로).

## 보고 형식 (이것만, 다른 말 없이)

문제 없는 지문은 나열하지 말고 마지막에 수만 적는다. 발견 항목은:

```
- <source_key> | <필드: tags[문장idx] / comprehensive#N / vocab "word" / svoc[idx].role / topic>
  현재: <저장된 내용 요지>
  문제: <왜 틀렸는지 한두 문장 — 원문 근거 인용>
  제안: <올바른 내용>
  확신: 높음|중간
```

마지막 줄: `검토 N지문 · 발견 M건 (높음 x·중간 y) · 이상 없음 K지문`
